# i18n — placeholder

grab is English-only today. This document captures the audit rationale for that decision and what would need to change if a future contributor wanted to add locales.

## Where strings live

| File | Kind |
|---|---|
| `src/utils.ps1` | Log messages (English, technical -- unlikely to need translation) |
| `src/tray.ps1` | Tray menu labels (`Show grab`, `Queue`, `Recent`, `Settings...`, `Copy diagnostics`, ...), Confirm dialog copy, About body |
| `src/settings.ps1` | Status-line messages ("Saved.", "Folder is not writeable: ...") |
| `src/popup.ps1` | Paste-tab status messages ("Added N. Switch to Queue tab..."), tab labels via XAML |
| `src/queue.ps1` | Log messages + toast strings ("Grabbed N file(s)") |
| `src/core.ps1` | Log messages (English) |
| `ui/popup.xaml` | Static labels: tab strip (`PASTE`/`QUEUE`/`RECENT`), section headers, arcade wordmark |
| `ui/settings.xaml` | Section labels (`DOWNLOADS`/`COOKIES`/`VIDEO`/...), field labels + captions |

## Rough string counts

Roughly 60 user-visible strings across .ps1 + .xaml. Log strings would stay English (they land in %APPDATA%\grab-app\logs where localisation adds noise for cross-language bug reports).

## Blockers today

1. Silkscreen / VT323 fonts are Latin-only. Non-Latin scripts would need alternate stacks and a smaller wordmark.
2. The arcade wordmark is `GRAB` -- a brand string, not translated.
3. Windows Speech / Narrator picks up `AutomationProperties.Name` values (added in audit v0.3.0-pass2 finding 5). Those would need locale binding too if we localised.

## Non-goals

Right-to-left layouts are out of scope. Every window uses left-aligned Grids without `FlowDirection` mirroring.

## When to revisit

If we start shipping outside personal use (e.g. a public release with a real audience), open a proper CP that:

1. Extracts every user-visible string into a resource dictionary (WPF `x:Static` with a `Resources` class).
2. Adds a `culture` config key that defaults to `[Globalization.CultureInfo]::CurrentUICulture`.
3. Wires font fallbacks so Silkscreen/VT323 gracefully hand off to a Latin-preserving substitute for the wordmark + a script-appropriate font for body copy.

Until then, English-only is intentional, not oversight.
